What CrossGuard Live needs, and why:

It compares your AWS IAM permissions against your Kubernetes RBAC rules to find places where a Kubernetes ServiceAccount can escalate into full AWS admin access. To do that safely, it needs read access to both — without ever seeing your long-term credentials.

1. Create an IAM role it can assume

In the AWS account you want to scan, create a role with this trust policy (replace YOUR_ACCOUNT_ID with this app's AWS account, and choose your own External ID):

Attach read-only IAM permissions (iam:List*, iam:Get*) at minimum. Copy the role's ARN into the field below.

2. Get your kubeconfig

This is the file that lets you (and this app) talk to your Kubernetes cluster. If you can already run kubectl get pods successfully, you already have one — find it by running echo $KUBECONFIG or checking ~/.kube/config. Use the Choose file button below to load it directly — nothing is uploaded anywhere except straight to your own scan.

Where does my data go?

Nothing is stored. Your role ARN and kubeconfig are used only for the duration of one scan, then discarded. See the project README for the full security model.
